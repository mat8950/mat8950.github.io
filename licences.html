Comprendre les licences

Guide du catalogue · mis à jour le 9 novembre 2026

La licence d'un logiciel fixe ce que vous avez le droit d'en faire : l'utiliser au travail, le modifier, l'héberger pour d'autres, l'intégrer à un produit que vous vendez. Sur ce site, chaque outil porte un badge de licence coloré. Le menu « Toutes licences » filtre le catalogue par famille ou par licence précise. Un clic sur un badge affiche tous les outils de la même famille.

Ce guide simplifie : ce n'est pas un avis juridique et seul le texte de la licence fait foi. Avant un usage commercial, lisez le fichier LICENSE de l'outil.

Libre — permissive

Vous faites presque tout ce que vous voulez : usage commercial, modification, revente, intégration dans un logiciel fermé. La seule obligation : garder la mention de copyright et le texte de la licence dans les copies.

  • MIT, ISC : quelques lignes, les plus simples.
  • Apache-2.0 : ajoute une licence explicite sur les brevets ; signaler les fichiers modifiés et garder le fichier NOTICE.
  • BSD-2-Clause / BSD-3-Clause : comme MIT ; la 3-Clause interdit d'utiliser le nom des auteurs pour votre publicité.
  • CC0-1.0, Unlicense : versement au domaine public, sans aucune condition.

Libre — copyleft

Mêmes libertés que les licences permissives, avec une règle de réciprocité : si vous distribuez une version modifiée (ou un programme qui l'intègre), elle doit rester sous la même licence, avec son code source. Utiliser l'outil ou l'auto-héberger pour vous-même n'impose rien.

  • GPL-2.0 / GPL-3.0 (copyleft fort) : tout programme distribué qui intègre du code GPL passe sous GPL. Proposer un service en ligne n'est pas une distribution : pas d'obligation.
  • AGPL-3.0 : la GPL avec une clause réseau. Si vous modifiez l'outil et que des utilisateurs s'en servent par le réseau (SaaS, intranet), ils doivent pouvoir obtenir le code de votre version. Très fréquente sur les outils auto-hébergeables.
  • LGPL (copyleft faible) : une bibliothèque LGPL peut être utilisée par un logiciel fermé ; seules les modifications de la bibliothèque elle-même doivent être partagées.
  • MPL-2.0, EPL-2.0 (copyleft par fichier) : seuls les fichiers modifiés restent sous la licence ; ils peuvent cohabiter avec du code fermé.
  • EUPL-1.2 : licence copyleft de l'Union européenne, compatible avec GPL, AGPL, MPL et d'autres.
  • CC-BY-SA : équivalent pour les contenus (documentation, listes) : réutilisation libre si vous partagez sous la même licence.

Voir les outils sous licence copyleft

Open-core

Le cœur du logiciel est libre (MIT, Apache-2.0, AGPL…) ; des modules « entreprise » (SSO, journal d'audit, gestion fine des droits, support) sont sous licence commerciale, souvent dans un dossier ee/ du dépôt. L'édition communautaire s'auto-héberge gratuitement ; les fonctions avancées demandent un abonnement.

Sur ce site, la licence s'écrit X+EE : MIT+EE (GitLab, Infisical, Authentik), AGPL-3.0+EE (Metabase, Mattermost, Twenty), Apache-2.0+EE (Dokploy, SuperTokens).

Source disponible (non libre)

Le code est public, vous pouvez le lire et souvent l'utiliser en interne, mais des restrictions empêchent de parler de logiciel libre : pas de revente, pas d'offre hébergée concurrente, ou pas d'usage commercial du tout. Ces licences ne sont pas approuvées par l'OSI.

  • BUSL-1.1 (Business Source License : Terraform, Vault) : usage en production limité par une clause propre à chaque éditeur (souvent : tout sauf un service concurrent). Chaque version devient libre à une date fixée, au plus tard 4 ans après sa sortie.
  • FSL (Functional Source License : GitButler) : tout usage sauf concurrent ; chaque version devient MIT ou Apache-2.0 après 2 ans.
  • SSPL-1.0 (MongoDB) : qui propose le logiciel en service doit publier le code de tout son service (supervision, sauvegardes, interface…). En pratique, un accord commercial.
  • Elastic-2.0 : interdit de le proposer à des tiers en service hébergé ou managé, et de contourner les clés de licence.
  • SUL (Sustainable Use License : n8n) : usage pour vos besoins internes ou personnels ; pas de revente ni d'hébergement commercial pour des clients.
  • PolyForm : variantes à lire (Noncommercial : aucun usage commercial ; Perimeter : tout sauf un produit concurrent).
  • Commons Clause : ajoutée à une licence libre, elle retire le droit de vendre le logiciel ou un service qui repose dessus.
  • CC-BY-NC : contenus réutilisables, mais pas à des fins commerciales.
  • Sans licence (« sans licence » sur le badge) : le droit d'auteur s'applique par défaut. Vous pouvez lire le code (et le forker sur GitHub), mais pas le réutiliser ni le redistribuer légalement.
  • Licences maison (Remotion, Open WebUI…) et licences de modèles d'IA à usages restreints (OpenRAIL) : lire le texte au cas par cas.

Propriétaire

Code fermé : l'usage est réglé par les conditions de l'éditeur (abonnement, offre gratuite limitée, licence par poste). Souvent un service en ligne non auto-hébergeable. Ces outils restent au catalogue quand ils sont des références de leur domaine (Postman, VMware, ChatGPT).

Licence inconnue

Le site n'a pas trouvé le dépôt de l'outil (site officiel sans lien sûr vers GitHub), ou GitHub ne reconnaît pas la licence. Vérifiez sur le site de l'outil avant de l'adopter.

Comment le site classe un outil

  1. La licence vient de GitHub, qui la détecte sur le dépôt (identifiant SPDX : MIT, AGPL-3.0…). Pour un outil présenté par son site officiel, le dépôt est retrouvé automatiquement quand le lien est sûr.
  2. Licence non reconnue par GitHub (texte modifié, licence maison) : le fichier LICENSE est lu et la valeur saisie à la main.
  3. Licences au choix (« X OR Y ») : la plus libre compte, puisque vous pouvez la choisir. Exemple : Redis (AGPL-3.0 OR SSPL-1.0 OR RSALv2) est classé copyleft.
  4. Licences cumulées (« X AND Y ») : la plus contraignante compte.
  5. X+EE : open-core si le cœur X est libre ; sinon source disponible (n8n : SUL+EE).
  6. Dépôt sans fichier de licence : source disponible (tous droits réservés).

Les données sont aussi publiées pour les IA et les scripts : catalogue JSON (champs license et license_family), llms.txt. Une erreur de classement ? Ouvrez une issue.

Lexique

Logiciel libre
Logiciel qui garantit quatre libertés (définition de la FSF) : l'utiliser pour tout usage, étudier son code, le modifier, redistribuer des copies modifiées ou non.
Open source
Définition de l'OSI, aux critères très proches. En pratique, les mêmes licences sont à la fois libres et open source.
Copyleft
Obligation de garder la même licence pour les versions modifiées que l'on distribue.
Distribuer
Donner ou vendre une copie : binaire, image Docker, application. Héberger un service en ligne n'est pas une distribution, sauf pour l'AGPL et la SSPL qui couvrent l'usage par le réseau.
Source disponible (source-available, fair source)
Code public mais droits limités, parfois libéré après un délai (BUSL, FSL).
SPDX
Liste standard des identifiants de licence (Apache-2.0, GPL-3.0-or-later…), utilisée par GitHub et par ce site.
